# 怪异任务编辑器（PWA）· v1.0.0

在浏览器里编辑 **MONSTER HUNTER RISE 16.0.2（破解 Switch）** 的「怪异任务」列表。
支持**在线直改 Switch 内存**，也支持**离线编辑任务文件**。

---

## 🚀 快速开始

### 1. 启动中转服务

- **手机/Termux**：点 `中转服务.sh`
- **电脑**：双击 `中转服务.py`（Windows 会前台运行，方便看日志）

启动后会打印两个地址：

```
本地      : http://127.0.0.1:6001/     ← 在这台机器上打开
局域网    : http://192.168.x.x:6001/   ← 手机/平板打开
NS (sys-botbase) : 192.168.1.5:6000    ← Switch 的地址（可在设置里改）
```

### 2. 打开网页

浏览器访问上面的地址即可。

> **PWA 安装**：只有 `http://127.0.0.1:6001/` 或 `https://` 才能装成 App。
> 用局域网 IP 打开时 Service Worker 不会注册（**但功能完全正常**，只是没有离线缓存）。

### 3. 读取任务

点工具栏 **📥 读取**（或连接后自动读取），会一次性把 200 个槽拉下来。

## ✨ 主要功能

### 🔎 筛选面板（多选组合）

工具栏的 **🔎 筛选** 按钮打开，**所有条件可组合**：

| 区域 | 逻辑 |
|------|------|
| **状态**（锁定 / 新任务 / 超特通关 / 超特许可 / 超特新） | 勾多个 = **全部满足**（AND）|
| **目标数量 / 地图 / 怪物** | 选多个 = **任一满足**（OR）|
| **等级区间 / 怪异★区间** | 数值范围 |

底部会显示**当前数据的实际范围**（等级 / 怪异★ 的 min~max），方便你填。

### ⚡ 批量修改

**范围**（4 选 1）：

| 范围 | 说明 |
|------|------|
| **当前列表（N 个）** ⭐ | 先用筛选/搜索挑出来再批量改，最实用 |
| **全部（N 个）** | 所有现有任务 |
| **槽位区间** | 手填"第几个"（1~200）|
| **空槽位（N 个）** | 空格子 |

**逐个变化**：填 `+1` / `-1` / `+5` 可以给每个任务改成不同值（空着 = 全部同值）。

- 填了步长才会出现 **「谁先拿值」** 下拉：**默认（列表/槽位顺序）** / 按序号 / 按编号
- 选 **当前列表** 且保持默认时，**按你在界面看到的顺序**依次取值 ✅

**⚠️ 两个安全设计**：

1. 数字字段的输入框**默认留空**（以前默认填 300，容易误改）→ **不填点开始会提示**
2. 批量改**怪物**时，可以勾 **「同时改等级」**（怪1 用主等级，其余用副等级）

### 🧨 清空所有任务

**⚙️ 设置 → 危险操作**

- **保留"第 1 个有任务的槽"**（第 1 槽为空则保留最靠前的有任务槽）
- 需要**手动输入「清空」两个字** + 二次确认
- ⚡ **大块写入，约 2~5 秒**（不是逐个写，不会等好几分钟）

### ♻️ 恢复所有已删除任务

**⚙️ 设置 → 危险操作**

**判定规则**（三条都满足才恢复）：

```
① 编号 == FFFFFFFF        ← 是个"空槽"
② 怪1ID ≠ 0 且 ≠ FFFFFFFF ← 排除"从没用过的槽"
③ 怪1ID 在怪物表里能查到   ← 再保险一道
```

**恢复成**：

| 字段 | 值 |
|------|-----|
| **序号** | 从**序号计数器**往后发号，一个用一下（`cur, cur+1, …`）|
| **编号** | `700000 + 槽位` |
| **叹号** | `1`（显示"新任务"）|
| **计数器** | 最后写成 `cur + 恢复数量` |

**⚠️ 怪物 / 地图 / 等级 / 限制等数据本来就在**（游戏删除时只清序号/编号/叹号），**恢复后直接可用**。

### 📥 打开文件（离线模式）

点 **📥 打开文件** 选一个 **导出的 JSON**，就能**离线编辑**（不需要连 Switch）。
改完可以**导出**，之后再从网页写回 Switch。

## 🔧 开发 / 发版流程

### ⚠️ 重要：改代码只改 `js/`，不要改 `index.html`

`index.html` 是**生成出来的**。改完 `js/` 后必须跑：

```bash
python3 botbase/_inline.py
```

它会做两件事：

1. 把 `js/*.js` 内联进 `index.html`
2. **读 `js/data.js` 的 `APP_VERSION`，写进 `sw.js` 的缓存名**

### 发新版的完整步骤

1. 改 `js/` 里的代码
2. 改 `js/data.js` 里的版本号：
   ```js
   var APP_VERSION = 'v1.0.1';   // ← 改成新版本号
   ```
3. 跑同步：
   ```bash
   python3 botbase/_inline.py
   ```
4. **完事** ✅

**用户端更新方式**：

- **点标题栏的版本号** → 自动检查 → 有新版就清缓存刷新
- 或者**直接刷新页面**（网络优先，通常也能拿到新版）

## 📦 缓存策略（PWA）

**网络优先（Network-First）**：

```
打开页面 → 先请求网络
            ├─ 成功 → 用最新版，顺手更新缓存
            └─ 失败 → 用缓存兜底（离线也能看界面）
```

| 内容 | 是否缓存 |
|------|---------|
| `index.html` / `manifest` / 图标 | ✅ 缓存（网络优先）|
| `/cmd`（Switch 命令接口）| ❌ 不缓存 |
| 跨域请求 | ❌ 直接放行 |
| 带 `?_t=` 的请求（点"检查更新"）| ❌ 走网络，不写缓存 |

**缓存名会随版本自动变**（`anomaly-forge-v1.0.0`），
所以**发新版后 `activate` 时能自动清掉上一版缓存** ✅

## 🧠 内存结构（逆向笔记）

### 任务数组在哪

```
p1 = *(main + 0x12A58748)      ← 用 peekMain 读（NSO 相对偏移）
p2 = *(p1 + 0x100)
p3 = *(p2 + 0x28)
base = p3 + 0x20               ← 任务[0] 的地址
任务[i] = base + i * 0x74
```

### 每个任务 116 字节（0x74）

| 偏移 | 字段 | 说明 |
|------|------|------|
| `+0x00` | **序号** | 第几个获得（排名相关）|
| `+0x04` | **编号** | 恒 = `700000 + 槽位` |
| `+0x08` | 等级 | 0~300 |
| `+0x0C` | 类型 | 1 狩猎 / 2 讨伐 |
| `+0x10` | 未知10 | 固定 300 |
| `+0x14` | 锁定 | |
| `+0x18` | 目标数量 | 1~5 |
| `+0x1C`~`+0x30` | **怪1~5 ID + 乱入ID** | |
| `+0x38`~`+0x4C` | 怪1~5级 + 乱入级 | |
| `+0x54` | 地图 | |
| `+0x58` | 时间限制 | |
| `+0x5C` | 猫车 | |
| `+0x60` | 人数 | |
| `+0x64` | 出发 | |
| `+0x68` | **叹号** | 0 无 / 1 有 |
| `+0x6C` | 调整前级 | |
| `+0x70` | 超特通过 | |
| `+0x71` | 超特许可 | |
| `+0x72` | 超特叹号 | |

### 删除标记

**游戏"删除"一个任务 = 写这三处**：

| 偏移 | 值 |
|------|-----|
| `+0x00` 序号 | `0xFFFFFFFF` |
| `+0x04` 编号 | `0xFFFFFFFF` |
| `+0x68` 叹号 | `256`（`0x100`）|

**其它字节原样留着** → 所以**能"恢复"** ✅

### 序号计数器

```
reg0 = *(main + 0x12A58748)
reg1 = *(reg0 + 0x100)
addr = reg1 + 0x34        ← 计数器地址（4 字节）
```

- **读到的是"下一个新任务会拿到的序号"**
- 游戏获得新怪异任务时取这个值，然后 **+1**

## ⚠️ 已知坑 / 注意事项

### sys-botbase 的返回格式

**读回来的 hex 是"第 1 个字节是最低位"**，不是普通大端/小端：

```
返回: 70F6C2D227000000
实际: 0x27D2C2F670
```

`memory.js` 的 `Mem.u64()` 已处理。

### peek / poke 的参数

| 命令 | 参数含义 |
|------|---------|
| `peek <off> <n>` | **相对 heap**（SW 会 +heap_base）|
| `peekMain <off> <n>` | **相对 main NSO**（SW 会 +main_nso_base）|
| `poke` / `pokeMain` | 同上，**数据必须带 `0x` 前缀** |

**⚠️ 老版本 sys-botbase 没有 `peekAbsolute`** —— 本项目用 `heapBase`/`mainNsoBase` 自己算相对偏移，兼容性更好 ✅

### 槽位显示从 1 开始

- **界面显示**：`第 1 个` ~ `第 200 个`
- **内部索引**：`0` ~ `199`
- 转换：显示 `+1`，计算 `-1`

### 怪物表可能不全

`data.js` 的 `MONSTERS` 目前 73 个 ID。遇到未收录的会显示 **`未知(0xXX)`**。

**发现新的可以自己加**：

```js
var MONSTERS = {
  0x3E: "赤甲兽",
  0x848: "怪异克服天廻龙",
  // 加这里...
};
```

## 🆘 常见问题

### 连不上中转

1. 中转服务起了吗？（看终端有没有打印"已启动"）
2. 地址对吗？（⚙️ 设置里改）
3. 同一个 WiFi 吗？
4. Switch 上 `sys-botbase` 在跑吗？（金手指加载器里看）

### 读到 0 个任务

- 确认**游戏已经打开**（在标题界面不行，要进游戏）
- 确认是 **MONSTER HUNTER RISE 16.0.2**

### 改了代码没生效

1. **改的是 `js/` 还是 `index.html`？** 必须改 `js/`
2. **跑 `python3 botbase/_inline.py` 了吗？**
3. **浏览器缓存**：点标题栏版本号强制更新，或 `Ctrl+Shift+R`

### 版本号没变

- 检查 `js/data.js` 第 8 行的 `APP_VERSION`
- 跑完 `_inline.py` 后看输出有没有 `✅ sw.js 缓存名 → ...`
